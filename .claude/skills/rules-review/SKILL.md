## 手順

1. 変更ファイルを列挙する: `git diff HEAD --name-only; git ls-files --others --exclude-standard`
2. `.claude/rules/*.md` それぞれの frontmatter の `paths` を確認し、変更ファイルにマッチするものだけを担当として割り当てる
   （`paths` を持たないルールファイルがあれば、変更が1つでもあれば常に対象。マッチ0件のルールは起動しない）
3. `rules-reviewer` サブエージェント（`.claude/agents/rules-reviewer.md` の定義）を**1メッセージでまとめて並列起動**する（1呼び出し = ルールファイル1つ × そのルールにマッチする変更ファイル群）
4. 結果を集約し修正する
   - Critical / Warning は修正する（ユーザーの意図に関わる場合は独断せず確認する）
   - Info は報告のみ
   - **レビュアーの fail を鵜呑みにしない**。修正前にルール原文と該当行を自分でも確認する
5. 修正したファイルを担当するレビュアーだけ再起動する（最大3周。収束しなければ人間に判断を仰ぐ）
6. 全解消したら `.claude/hooks/review-gate.sh --pass` を実行する
7. 照合マトリクス・修正一覧・偽陽性として棄却した報告をユーザーへ報告する

## 注意

- `.claude/rules/*.md` が1つも存在しない場合は、照合対象0件としてそのまま手順6へ進む
- マーカーは**作業ツリーの内容ハッシュ**。コミットを分割しても失効しないが、ファイルを変更すると失効し再レビューが必要になる
- レビューで見逃しが見つかったら、**違反例（before/after）をルールファイルに追記する**
  （few-shot が次回以降の検出率を上げる。これがこの運用のメンテナンス作業）
- 緊急時のバイパスはコミットコマンドの先頭に `SKIP_RULES_REVIEW=1` を人間が付けたときのみ有効。**このスキル自身が自発的に付けることは禁止**
